# NAMELESS 404 Premium v0.26 — QA de latencia de entrada

**Fecha:** 29/10/2026 · **Objetivo:** corregir la respuesta irregular de teclado, ratón, táctil y mando observada por el jugador.

## Causa raíz localizada en v0.25

- El bloqueo global de 68 ms en `doKey()` descartaba una segunda pulsación diferente incluso si era válida.
- `if(ev.repeat)return` anulaba la repetición normal del teclado sin ofrecer una repetición propia.
- Los botones de la cruceta utilizaban `click`, que se produce después de levantar el dedo o ratón.
- Los mandos se consultaban cada 85 ms y repetían direcciones cada 185 ms.
- El lanzamiento en `127.0.0.1:8765` no declaraba explícitamente desactivada la caché de HTML/JS/CSS.

## Corrección

- `src/premium/ResponsiveInput.ts`: planificador de entrada de primera pulsación inmediata; primera repetición a 185 ms, siguientes a 92 ms. No acumula una ráfaga cuando un fotograma tarda más de lo normal. Varias fuentes y direcciones tienen estados independientes.
- `src/bootstrap.ts`: teclado (`keydown`/`keyup`), pointer (`pointerdown`, `pointerup`, `pointercancel`), y Gamepad API comparten el mismo planificador. El sistema operativo puede emitir `keydown` repetidos; no producen dobles movimientos. Se conserva `click` para navegación por teclado y accesibilidad.
- Eventos `pointerdown` se procesan sin esperar a `pointerup`; el `click` posterior se consume y no ejecuta la acción dos veces, incluso al mantener el botón más de 900 ms.
- El mando se consulta cada ~22 ms (sujeto a `requestAnimationFrame` y disponibilidad del navegador).
- Al perder el foco o mostrar un diálogo se limpian teclas mantenidas; las capturas `pointercancel` también liberan la cruceta.
- `INICIAR-LINUX.sh`: `Cache-Control: no-store, max-age=0` para impedir que el navegador sirva el bundle de una versión anterior, manteniendo el puerto y el mismo origen para los guardados.

## Pruebas manuales recomendadas (en el dispositivo objetivo)

1. Iniciar `./INICIAR-LINUX.sh`, verificar la etiqueta `V 0.26.0 INPUT RESPONSE`.
2. Pulsar rápidamente izquierda y derecha: ambos giros deben ejecutarse, sin saltarse ninguno.
3. Mantener una flecha / cruceta: primer paso inmediato, pausa corta y repetición regular; soltar detiene el movimiento.
4. Tocar una vez **Cambiar mundo**: un solo cambio real↔RPG.
5. En el menú **Diagnóstico gráfico**, mirar el motor activo y los FPS; un FPS muy bajo también deteriora la sensación de respuesta, independientemente del sistema de entrada.
6. Comprobar una partida guardada de versiones anteriores y reabrirla después de reiniciar el navegador.

**Alcance estricto:** se demuestra la corrección del planificador y las pruebas en un navegador emulado. No se ha medido la latencia de pantalla/USB de Linux Mint ni garantizado un umbral universal de 16 ms.
